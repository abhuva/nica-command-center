## Configuration and portability gaps

- Homepage derives the vault from its parent directory.
- Calendar and VaultGraph derive the vault from two parent directories.
- Email defaults `vaultRoot` to `../..`.
- The launchers invoke `./Tools` relative to the vault root.
- Beantime's managed Fava port is hard-coded to `3464`.
- `Calendar/.env.example` exists locally but is ignored by the broad `.env.*`
  rule, so a fresh checkout lacks the documented template.
- Root defaults contain a personal Beantime account and must be generalized.

These gaps must be resolved through explicit configuration such as
`NICA_VAULT_ROOT` and separate runtime-state roots before production cutover.

## Security/history findings

- The Calendar runbook records a previously exposed Google API key. Rotation
  or revocation remains mandatory even though a limited history signature scan
  found no obvious Google, GitHub, AWS, or private-key signatures.
- Sensitive configuration filenames were not found as tracked history entries
  during the initial audit.
- A dedicated credential scanner has not yet been run.
- Proposal extracts and generated Calendar events already occur in Git history;
  deleting them only in a new commit would not make a safe import.
